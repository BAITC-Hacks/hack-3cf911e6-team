# HackAlem AI (репетиция) — трек «Агентные системы»

Два лёгких кейса одним репозиторием: **классификатор обращений** и **фильтр алертов**.
Стек: Python 3.8+, только стандартная библиотека — ставить ничего не нужно.

## Файлы

| Файл | Что это |
|---|---|
| `classify_messages.py` | Кейс 1: категория + черновик ответа для каждого обращения |
| `messages.txt` | 5 обращений из задания (одно на строку) |
| `filter_alerts.py` | Кейс 2: из потока событий оставляет только `critical` |
| `events.json` | 8 событий из задания (`info` / `warn` / `critical`) |

## Как запустить

```bash
git clone https://github.com/BAITC-Hacks/hack-3cf911e6-team.git
cd hack-3cf911e6-team

python classify_messages.py          # кейс 1  (Windows: py classify_messages.py)
python filter_alerts.py              # кейс 2
```

Дополнительно: `python classify_messages.py --json` — машиночитаемый вывод;
`python filter_alerts.py other.json` — другой файл того же формата.
Если в `cmd.exe` кириллица выводится квадратами — выполните `chcp 65001`.

## Что получилось

**Кейс 1.** Скрипт печатает для каждого обращения категорию, сработавшие сигналы, тему
и один черновик ответа на русском. Рубрика: `справка` — просят информацию или документ;
`жалоба` — сообщают о проблеме или недовольстве; `другое` — запись на приём, предложения,
заявки. На данных задания: **справка — №1, №5; жалоба — №2, №4; другое — №3.**

Категория определяется правилами: взвешенные маркеры-стеммы по трём категориям, побеждает
максимальный балл; нет ни одного маркера — честное `другое`. Отрыв меньше 2 баллов даёт
пометку «низкая уверенность», и такие обращения выводятся списком на ручную проверку —
это дешёвый контроль качества вместо молчаливой ошибки. Черновик выбирается по паре
(категория, тема): например, жалоба + тема «ит» → ответ про заявку в ИТ-службу.

**Кейс 2.** Скрипт печатает только критичные события и итоговую фразу:

```
Источник: events.json — всего событий: 8
------------------------------------------------------------
[CRITICAL] #1 storage: disk 90%
[CRITICAL] #4 payments: payment failed
[CRITICAL] #6 db: db timeout
------------------------------------------------------------
критичных 3
```

Понимает оба формата (массив и `{"events": [...]}`), не зависит от регистра уровня, а
события с нераспознанным уровнем не теряются молча — о них пишется предупреждение в stderr.

## Честные ограничения

- Сроки и подразделения в шаблонах ответов (`1–2 рабочих дня`, «учебный отдел») — заглушки:
  под реальный регламент вуза их нужно заменить.
- У `classify_messages.py` есть опциональный режим `--llm`: категории для всех обращений
  одним запросом к Claude (структурированный ответ по JSON-схеме). Он требует
  `pip install anthropic` и `ANTHROPIC_API_KEY`; при отсутствии ключа, сети или расхождении
  ответа со схемой скрипт не падает, а возвращается к правилам. Основной проверенный
  путь — правила: он работает без сети, ключей и зависимостей.
